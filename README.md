# MineKingdom

Minecraft 1.20.1 / Forge 47.2.0 / Java 17 기반 왕국 건설 모드.

## 개발 환경

```bash
./gradlew runClient   # 클라이언트 실행
./gradlew build       # 모드 jar 빌드
```

Java 17이 필요합니다. `JAVA_HOME`이 17을 가리키지 않는다면 다음처럼 지정합니다.

```bash
JAVA_HOME=/path/to/jdk-17 ./gradlew runClient
```

## 현재 구현: 시민(Citizen)

크리에이티브 "생성 알" 탭의 **시민 생성 알**로 소환합니다.

- 플레이어 모델을 사용하며 소환 시 남/녀가 무작위로 결정됩니다.
  - 남성: 클래식(스티브) 모델 + 스티브 스킨
  - 여성: 슬림(알렉스) 모델 + 알렉스 스킨
- 배회, 문 열기, 물에 뜨기, 플레이어 쳐다보기 AI를 가지며 길찾기로 이동합니다.
- 걷는 속도는 플레이어와 비슷한 초당 약 4.2블록입니다. 지상 이동 속도는 특성값에 비례하지
  않고, 실측상 `42.6 × (이동속도 특성 × goal 속도 계수)²` blocks/s에 가깝습니다.
  (0.25 → 2.66, 0.35 → 5.23, 0.45 → 8.55 b/s 실측)
- 멀리 떨어져도 디스폰되지 않습니다.

### 중립 몹

도망치지 않으며, 공격받으면 반격합니다. 한 번 화가 나면 20~39초간 유지되고 그 상태는
저장됩니다. 근처의 다른 시민도 함께 반응합니다. 기본 공격력은 2이며, 무기를 들고 있으면
그 무기의 공격력이 더해집니다.

### 인벤토리

주민과 동일하게 8칸 인벤토리를 가집니다. 선택된 슬롯의 아이템이 오른손에 복사되어
플레이어처럼 들고 있는 형태로 렌더링됩니다. 곡괭이는 곡괭이 형태로, 블록은 블록 형태로
각 아이템의 고유 모델대로 표시됩니다.

바닥에 떨어진 아이템을 밟고 지나가면 인벤토리에 담습니다. 아이템 쪽으로 일부러 이동하지는
않으며, 인벤토리가 가득 차면 줍지 않습니다. (`mobGriefing` 게임규칙을 따릅니다.)

### 채굴

시민에게 채굴을 시키면 다음 규칙으로 움직입니다.

1. 반경 6블록(수직 3블록) 안에서 **드러난** 돌·광석을 다음 순서로 고릅니다.
   ① 광석 → ② 캐도 설 자리가 줄지 않는 블록 → ③ 나머지. 같은 순위 안에서는 가까운 순입니다.
   ②는 블록을 없앴을 때 서 있을 수 있는 위치가 그 블록·위·아래 세 칸에서만 바뀐다는 점을
   이용해 값싸게 판정하며, 발판을 스스로 파내는 선택을 뒤로 미룹니다(가까운 비광석 24개까지).
   단, 실제로 **눈에 보이는** 블록만 대상입니다. 다른 블록에 가려져 있으면 캘 수 없고,
   보이는 위치까지 걸어가야 합니다. 채굴 사거리는 3블록입니다.
2. 자기 발밑 블록과 자기가 서 있는 기둥은 캐지 않습니다.
3. 캤을 때 액체가 새거나 위의 모래·자갈이 떨어질 블록은 캐지 않습니다.
4. 이동은 단차 ±1, 머리 공간 2칸인 걸음만 사용합니다. 모든 걸음이 역방향으로도 걸을 수
   있으므로 항상 되돌아올 수 있습니다. 이 걸음으로 닿을 수 없는 블록은 대상에서 제외됩니다.
5. 캔 뒤에 최근 지나온 발판으로 되돌아갈 수 없게 되는 블록은 캐지 않습니다. 규칙 4는 그
   순간의 지형만 보지만 채굴은 지형을 바꾸므로, 최근 서 있던 위치를 기억해 두고 해당 블록을
   제거한 가정 하에 다시 경로를 확인합니다.
6. 주변에 캘 것이 없으면 24블록까지 성기게 훑어 광맥을 찾아 이동한 뒤 다시 탐색합니다.
   그래도 없을 때만 채굴을 멈춥니다.

천장에 막혀 올라갈 수 없으면 머리 위 블록을 캐서 뚫습니다. 캘 수도 쌓을 수도 없어 정말로
갇힌 경우에는 조용히 멈추지 않고 서버 로그와 `/ctest mining report`의 `stuck` 항목으로
드러납니다.

그럼에도 지형 변화로 갇힌 경우, 인벤토리의 블록을 발밑에 쌓아 올라옵니다(`mobGriefing` 준수).
쌓을 블록이 없으면 주변 돌을 캐서 그 드롭을 주워 보충합니다. 올라갈 수 있는지는 좌표 하나가
아니라 **시민의 실제 충돌 상자를 1블록 위로 옮겨** 판정합니다. 시민 폭이 0.6이라 옆 칸에
걸친 블록이 점프를 막는데, 좌표 한 칸만 보면 그게 안 잡혀 천장에 머리를 박으며 무한히
점프하게 됩니다. 막는 블록이 전부 캘 수 있는 것이면 먼저 캐고, 하나라도 못 캐면 그 시민은
일정 시간 동안 쌓기에 의존하지 않는 경로만 계획합니다. 쌓기는 경로계획이 요구한 칸
수만큼만 이루어지며, **자기가 놓은 블록의 좌표를 기억**해 두었다가 필요하면 그 블록만 다시
캐서 내려옵니다. 조약돌은 채굴 대상이 아니므로 이 기억이 없으면 자기 기둥 위에 갇힙니다.
(남이 놓은 조약돌은 여전히 건드리지 않습니다.)

이동 중 실제로 움직이지도(2블록 이상 이동), 블록을 캐지도, 놓지도 않은 채 200틱이 지나면 그
이동은 실패로 처리되어 목표가 제어권을 놓습니다. **단, 판정이 났다고 해서 그 틱의 작업이
막히지는 않습니다** — 정지 상태를 푸는 네 가지(이동·캐기·쌓기·구간 넘김)가 모두 이동 코드
안에 있으므로, 판정 즉시 반환해 버리면 스스로는 영원히 빠져나올 수 없습니다. 카운터 갱신은
매 틱 맨 앞에서, 실패 판정은 작업을 마친 뒤에 합니다.

여기에 더해 **600틱짜리 2차 감시**가 있습니다. 이쪽은 캐기·쌓기를 진행으로 치지 않고 오직
**순변위 2블록** 또는 **구간 넘김**만 인정합니다. 블록을 놓았다가 그 블록을 다시 캐는 왕복은
캐기·쌓기 카운터를 계속 움직여 1차 감시를 영원히 통과하지만, 구간은 결코 넘기지 못하므로
2차 감시에 걸립니다. 진행 판정을 블록 좌표 변화가 아니라 **이동
거리**로 재는 이유는, 바닐라 길찾기가 시민을 블록 경계에서 왕복시키면 좌표는 매 틱 바뀌면서
실제로는 제자리이기 때문입니다.

바닐라 길찾기가 "갈 수 있다"고 보고해도 60틱 동안 2블록을 못 가면 그 판단을 200틱간 불신하고
굴착 계획으로 전환합니다. 바닐라는 "파거나 쌓아야 갈 수 있는 길"을 모르면서도 도달 가능하다고
답하는 경우가 있어, 이것이 없으면 계획을 손에 쥔 채 정지합니다.

목적지가 탐색 상자(수평 8, 수직 6)보다 멀면 한 번에 계획이 나오지 않으므로, 가장 가까이
간 지점까지의 **부분 계획**을 세우고 도착 후 다시 계획합니다. 이때 중간 목적지는 "지금
설 수 있는 곳"이 아니라 **"그 계획을 수행한 뒤에 설 수 있는 곳"**으로 판정합니다. 파거나
쌓아서 만드는 발판도 발판이기 때문입니다. (헤엄으로만 닿는 지점은 제외됩니다.)

막혔다고 해서 복귀 자체가 끝나지는 않습니다. 100틱 물러났다가 선 자리에서 다시 계획을 세우며,
전체 제한시간(3600틱)에 걸려야 비로소 실패로 기록됩니다. 실패로 기록된 시민은 `stuck` 표시가
남아, 작업이 없는 상태에서도 탈출 목표가 계속 그 시민을 구조하려 시도합니다.

현재는 곡괭이 없이도 캘 수 있으며, 채굴 속도는 `CitizenEntity#getDestroyProgressPerTick`
한 곳에서 결정됩니다. 곡괭이를 도입할 때 이 메서드만 교체하면 됩니다.

## 진단 도구

시민이 "가만히 있다"는 현상은 원인이 여러 가지라 눈으로는 구분되지 않습니다. 아래 도구는
전부 `key=value` 한 줄 포맷이며, 채팅과 서버 로그에 동시에 나가므로 grep으로 걸러집니다.

### `/ctest why` — 지금 무엇을 하고 있는가 (`CZWHY`)

```
CZWHY uuid=d0d90936 task=returning stuck=false at=205,62,207 walkBanned=false
  driver=return target=205,72,209 mode=DIGGING age=0 leg=3/6 legTicks=0
  stall=9 walkStill=0 placed=0 dig=204,57,207@22%
  plans=2 empty=0 legTimeouts=0 walkBans=0 stallTrips=0 goals=[4:CitizenReturnGoal]
```

`driver`/`target`은 **실제로 구동 중인 목표가 향하는 곳**입니다. 목표마다 목적지가 다르므로
(탈출 목표는 발자취 앵커로 갑니다) 이걸 보지 않고 복귀지점 기준으로 추정하면 아무도 하지
않는 여행을 설명하게 됩니다. `mode`는 WALKING / PLAN_MOVE / DIGGING / BUILDING / NO_PLAN /
ARRIVED / STALLED. `age`는 이 값이 갱신된 지 몇 틱 지났는지로, 큰 값은 아무도 구동하지 않고
있다는 뜻입니다.

### `/ctest why blocked` — 왜 못 나가는가 (`CZBLOCK`)

수평 4방향 × 단차 3 + 위로 쌓기 + 발판 뚫고 내려가기, 총 14개 출구를 하나씩 판정합니다.

```
CZBLOCK   north dy=+1 243,64,242 -> body blocked: UNBREAKABLE (bedrock at 243,64,242)
CZBLOCK   east  dy=+0 244,63,243 -> no floor (air at 244,62,243)
CZBLOCK   up(build)   243,64,243 -> head blocked: FALLING_ABOVE (gravel at 243,65,243)
CZBLOCK   down(own)   243,62,243 -> cannot cut footing: NOT_NATURAL (cobblestone)
```

굴착 거부 사유는 AIR / UNBREAKABLE / NOT_NATURAL / FALLING_ABOVE / FLUID_INSIDE /
FLUID_ADJACENT 여섯 가지로 구분됩니다. 경로계획은 이걸 전부 하나의 "안 됨"으로 합치기
때문에, 자갈에 막힌 시민과 플레이어 건축물에 막힌 시민이 밖에서는 똑같아 보입니다.

### `/ctest watch <틱>` — 시간에 따라 무엇을 했는가 (`CZWATCH`)

1초마다 표본을 뜨고 종료 시 시민별로 판정합니다.

```
CZWATCH uuid=d0d90936 verdict=PROGRESSING samples=75 path=15.7 net=10.1 closed=+10.1
  mined=30 from=206.0,52.0,206.0 to=205.4,62.0,207.5 target=205,72,209
  modes=[PLAN_MOVE:6,DIGGING:69]
```

`verdict`는 FROZEN(총 이동 2블록 미만) / OSCILLATING(움직였으나 순변위 2블록 미만) /
WANDERING(움직였으나 목표에 가까워지지 않음) / PROGRESSING(목표까지 2블록 이상 좁힘).
스냅샷으로는 구분되지 않는 네 경우를 자동으로 갈라냅니다.

### 복귀 포기 사후기록 (`CZPOST`)

포기 시 서버 로그에 자동 기록됩니다.

```
CZPOST uuid=... at=243,63,243 home=205,72,209 ticks=3601 short=51.50 setOut=20.31
  placed=0 mined=42 driver=return target=205,72,209 mode=NONE
  plans=38 empty=35 legTimeouts=1 walkBans=0 stallTrips=0
```

`plans`/`empty` 비율이 핵심입니다. 위 예는 38회 탐색 중 35회가 빈 결과 — **계획 자체가 나온
적이 거의 없음**(갇힘). 반대로 `empty`가 낮은데 `legTimeouts`나 `stallTrips`가 크면 계획은
있었으나 걷지 못한 경우입니다. 이 둘은 원인도 대책도 전혀 다릅니다.

## 명령어

`/ctest`는 시민을 손으로 부려 보기 위한 테스트 명령어입니다 (권한 레벨 2 필요).

| 명령어 | 동작 |
| --- | --- |
| `/ctest select [범위] [n]` | 명령 위치 기준 범위 안의 가까운 시민 n명을 선택 (기본 범위 16, n 제한 없음) |
| `/ctest mining start` | 선택한 시민이 채굴 시작 |
| `/ctest mining stop` | 선택한 시민이 채굴 중지 |
| `/ctest mining report` | 시민별 채굴한 블록 수와 합계 출력 (노는 시민 확인용) |
| `/ctest mining reset` | 채굴 카운터 초기화 |
| `/ctest debug` | 시민별 계획 존재 여부 요약 |
| `/ctest why` | 시민별 **현재 이동 상태** (아래 참조) |
| `/ctest why blocked` | 선택된 첫 시민이 **왜 못 나가는지** 14개 출구별 사유 |
| `/ctest watch <틱>` | 지정 시간 동안 추적 시작 |
| `/ctest watch report` | 중간 집계 (추적 계속) |
| `/ctest watch stop` | 집계 출력 후 종료 |
| `/ctest home set` | 선택한 시민의 현위치를 복귀지점으로 기록 |
| `/ctest home return` | 선택한 시민을 복귀지점으로 복귀시킴 |
| `/ctest home report` | 선택한 시민의 복귀지점까지 거리와 도착 여부 집계 |
| `/ctest debug` | 선택한 시민의 현재 작업과 실행 중인 AI goal 출력 |

복귀는 길찾기로만 이뤄지며 순간이동은 사용하지 않습니다. 도착하거나 포기하면 서버 로그에
결과가 한 줄씩 남고, 출발 당시 거리가 함께 기록되어 실제로 이동했는지 로그만으로 확인할 수
있습니다. 도착 판정 기준은 1.5블록(`CitizenEntity.RETURN_ARRIVAL_DISTANCE`)입니다.

명령어는 시민을 고르고 작업을 바꾸는 일만 합니다. 동작 자체는 전부 엔티티에 있으므로,
나중에 직업 시스템이나 건물에서 부를 때는 `CitizenEntity#setTask(CitizenTask)`를 직접
호출하면 됩니다. 선택 기능이 필요 없다면 `CitizenSelectionManager`를 거치지 않아도 됩니다.

| 조작 | 동작 |
| --- | --- |
| 아이템을 들고 우클릭 | 해당 아이템을 인벤토리에 넣고 그 아이템을 들게 함 |
| 맨손으로 우클릭 | 다음으로 채워진 슬롯으로 전환 (들고 있는 아이템 변경) |
| 웅크린 채 맨손으로 우클릭 | 인벤토리 내용물을 전부 돌려받음 |

인벤토리 상태는 액션바에 표시되며, 시민이 죽으면 소지품을 전부 떨어뜨립니다.
